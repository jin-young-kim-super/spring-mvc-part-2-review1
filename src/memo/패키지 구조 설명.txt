패키지를 이미지에 첨부한 방식으로 설계한 단 1개의 이유 : web 기술을 바뀌어도 domain에는 전혀 영향이 없게 하도록(ex. 도메인 코드의 변경 등)
-> 도메인의 정의인 "화면,UI,기술 인프라 등의 영역을 제외한 시스템이 구현해야 하는 【핵심 비지니스 로직】영역이다. 
도메인이 【핵심 비지니스 로직】영역인 만큼 다른 곳으로부터 영향을 받으면 안 된다. 예를 들어 도메인 안에 web 기술 관련 코드가 들어 있다고 하면 
web 기술 변경 시 핵심 비지니스 로직에 영향을 줘서 예상치 못한 버그를 초래한다. web 관련 코드 기술 코드 변경 시 그에 따라 도메인 코드 수정이 들어가거나 하면 
핵심 비지니스의 로직이 오염돼 서비스가 잘 동작하지 않을 수가 있다. 또한 핵심 비지니스 로직 영역인 Domain은 매우 중요한 코드이며 새로 짜거나 변경이 되도록 일어나서는 안 된다.
그리고 무엇보다 Domain 코드가 제일 짜기 어렵기 때문에 되도록 그대로 재활용이 가능해야 한다, web이 바뀌더라도.....

결론 : 위와 같은 이유에 의해서 web은 Domain에 의존해도 괜찮지만, Domain은 절대 web에 의존해서는 안 된다.
그렇기 떄문에 Domain 디렉터리와 web 디렉터리를 철저하게 분리하여 web에서만 Domain을 의존하도록 하여야 한다.

ex) @Controller를 @RestController로 코드를 다 변경하든, 타임리프를 다른 템플릿 엔진으로 바꾸던 , 스프링을 다른 프레임워크로 바꾸던
, 서버를 Rest API로 통째로 변경 등등
위와 같이 하면 핵심 비지니스 로직 영역인 Domain은 그대로 재활용이 가능하다.
