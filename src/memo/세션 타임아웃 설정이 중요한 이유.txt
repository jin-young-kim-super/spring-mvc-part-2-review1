결론 : 대부분의 유저들은 로그아웃 버튼을 누르고 서비스를 종료하지 않고, 그냥 웹 브라우저를 닫기 떄문에 서버 입장에서 이 유저의 로그인 상태를 유지시켜야 할지 만료시켜야 할지 판단x
-> HTTP는 비연결(Connectionless), 즉 요청-응답이 끝나면 맺어져 있던 TCP/IP 연결을 종료한다. 고로 서버 입장에서는 사용자가 웹 브라우저를 닫았는지 알 방법이 전무하다. 
세션은 메모리에 저장돼는 것인데, 이런 웹 브라우저를 종료를 해서 서비스를 사용하지 않는 사용자의 세션이 계속해서 쌓이게 되면 메모리 부하가 생긴다. 
또한 세션 타임아웃을 설정하지 않고 무한정 유지된다면 해커가 한 번 탈취하고 무한정 부정 접근이 가능해진다.
이러한 문제를 해결하기 위하여 세션 타임아웃을 반드시 설정을 해야 하는 것이다. 


타임아웃 설정 시간을 어떻게 정할까?
-> 사용자가 요청을 보낸 마지막 시점을 기준으로 30분 후까지로 설정하는 것이 일반적이다. 
즉 사용자가 요청을 보낼 때마다 세션의 타임아웃을 30분으로 재초기화하는 것이다. 


session.getLastAccessedTime() : 세션과 연결된 사용자가 최근에 서버에 접근한 시간!!!
-> HttpSession은 위 기능을 이용해서 타임아웃을 할 지, 혹은 요청이 새로 올 때마다 최근 서버 접근 시간 + 30분을 하여 타임아웃 시간을 재설정한다.


세션 타임아웃 설정 패턴 2가지
1. 글로벌 적용 : 모든 세션에 똑같은 타임아웃 정책 적용
-> application.properties에 server.servlet.session.timeout=60를 설정하면 요청 때마다 타임아웃이 30분으로 초기화

2. 지역 적용 : 특정 세션에 대해서 특정한 타임아웃 정책 적용
-> HttpSession.sexMaxInactiveInterval(10000)
