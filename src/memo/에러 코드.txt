required.item.itemName=상품 이름은 필수입니다.
range.item.price=가격은 {0} ~ {1} 까지 허용합니다.
max.item.quantity=수량은 최대 {0} 까지 허용합니다.
totalPriceMin=가격 * 수량의 합은 {0}원 이상이어야 합니다. 현재 값 = {1}

위를 보고 한 가지 의문이 든다. 에러 코드명이 너무 길고 복잡하다. 이렇게까지 자세하게 적어야 하는가?라는 고민이 든다.
아래와 같이 그냥 간단하게 에러 코드를 적으면 되지 않나? 
ex)
required = 필수값입니다. 
range = 범위는 {0} ~ {1}까지 허용합니다. 
max = 최대 {0}까지 허용합니다. 

오류 메시지는 상황에 따라서 사용자에게 자세한 내용을 보여 줘야할 때도 있고, 그냥 대충 보여줘도 되는 떄가 있다. 
근데 만약에 HTML 파일이 몇 십개가 있고, 오류 메시지를 작성해야 하는데 HTML 파일마다 거기에 맞는 오류 코드를 따로 짜면 굉장히 오류 코드가 많아 진다. 
즉, 범용성이 떨어 진다. 
그래서 개발자들은 여러 HTML 파일에도 최소한의 오류 코드 정의로 공통적으로 적용하고 싶은 욕망이 있다. 
결론적으로 비록 오류 코드명이 길지만 스프링의 규칙에 맞춰서 딱 1번만 오류 코드를 설계해 놓으면 여러 HTML 파일에서 오류 메시지를 범용성 있게 적용 가능하다. 


정리
가장 좋은 방법은 범용성으로 사용하다가, 오류 메시지를 세밀하게 표현해야 하는 경우는 세밀한 오류 메시지가 적용되도록 오류 코드에 단계(규칙)을 두어 사용하는 방법이다. 
ex)
기본적으로는 아래와 같은 범용적인 오류 메시지를 사용. 그러다가 "아.. 이 부분은 사용자들에게 좀 많이 보여지는 오류 메시지이고 좀더 세밀하게 표현을 해야겠다"는 부분에 대해서 단계를 적용
required = 필수값입니다.
range = 범위는 {0} ~ {1}까지 허용합니다.
max = 최대 {0}까지 허용합니다.

핵심 장점 : 만약 기획자가 오류 메시지를 변경 요청을 하면 애플리케이션 코드는 전혀 건들 필요 없이, errors.properties 수정만으로
전체 오류 메시지 정책을 변경 가능하다.

스프링은 MessageCodesResolver 라는 것으로 이러한 기능을 지원한다


MessageCodesResolver 사용 예시
ex)
@Test
void setMessageCodesResolver_Field() {
    String[] messageCodes = messageCodesResolver.resolveMessageCodes("required", "item", "itemName", String.class);
    for (String messageCode : messageCodes) {
        System.out.println("messageCode = " + messageCode);
    }
    /**
     * messageCodesResolver.resolveMessageCodes("required", "item", "itemName", String.class) 내부 동작
     * -> "itemName"이라는 필드명을 넣어 줬기 때문에 BindinResult.addErros(new FieldError(...new String[]{"required.item.itemName","required.itemName",.....}))이 자동 생성
     * 출력 결과
     * messageCode = required.item.itemName(우선 순위1)
     * messageCode = required.itemName(우선 순위2)
     * messageCode = required.java.lang.String(우선 순위3) -
     * messageCode = required(우선 순위4)
     */
}
messageCodesResolver.resolveMessageCodes("required", "item", "itemName", String.class);
-> 여기서 만약에 상품명(itemName)이 필수로 입력이 돼 있다고 했을 떄 required.item.itemName가 정의돼 있다면
"상품명은 필수값"이 오류 메시지로 출력돼 버린다.
반드시 검증 로직을 거쳐서 거기에 맞는 오류 코드를 입력해줘야 한다는 점에 주의하자
예를 들어, 상품명이 비어 있는 검증 로직은 이미 통과한 상황이고, 근데 이 상품명이 문자가 아닌 숫자와 특수기호가 들어 갔다고 하자.
