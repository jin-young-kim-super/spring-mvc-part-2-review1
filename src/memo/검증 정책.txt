클라이언트 검증 vs 서버 검증
예를 들어, 상품명에 "컴퓨터%^%^&"를 입력한 경우 만약 상품명에 특수 문자가 포함되는 안 되는 경우라면 이 사용자의 입력값은 잘못된 입력값이다. 
그러나 현재 코드 로직 상 이러한 상품명도 정상 처리가 되버린다. 
또한 상품 가격에 "ㅋㅋㅋㅋㅋ"같은 숫자가 아닌 문자열의 경우 price 변수는 Integer 타입이기에 서버에서 BindingError을 일이키며 사용자에게는 이해가 안되는 whitelabel 404 page를 보여 준다. 
위와 같은 상황을 막기 위해 반드시 입력값에 대한 검증(validation)이 필수이다. 

그럼 이 검증을 클라이언트에서 하게 되면 어떻게 될까?
장점 : 입력값이 잘못됐음을 사용자에게 빠른 시간에 알려 준다(서버 검증은 일정 시간이 걸림)
단점 : 조작 가능성이 있다. PostMan을 통해서 서버로 보내 버리면 JS 코드의 검증 로직 처리를 거치지 않기 때문이다. 

그럼 서버 검증은?
장점 : 조작 가능성이 적다. 
단점 : 입력값의 잘못됨을 사용자에게 알려 주기까지 시간이 걸려서, 사용성이 매우 안좋아(고객 이탈 가능성)

결론 : 클라이언트 검증과 서버 검증을 적절히 섞어서 사용하되, 「최종적인」 검증인 서버에서 담당.
-> 클라이언트에서도 1차적으로 한 번 하고, 서버에서도 최종적으로 정말 맞는지 검증!
