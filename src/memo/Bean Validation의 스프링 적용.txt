Bean Validation의 스프링 적용?
-> 뭔말인지 첨에는 모른다. 저번에 언급을 하였는데 Bean Validation 즉 @NotBlank, @Max 등의 에노테이션 모음과 인터페이스 모음인 Bean Validation은 java 표준에서 제공하는 기능이다. 
스프링이 제공하는 기능이 아니다. (@Range 등은 하이버네이트에서 제공한다. 그러나 실무 대부분 하이버네이트 Bean Validator를 사용하므로 사용해도 ㄱㅊ)

그리고 아래에서도 보았듯이 자바 표준이 제공하는 만큼 사용하려면 여러 추가 코드가 필요하다. 
그러나 이 Bean Validation은 스프링 프레임워크과 이미 통합돼 있어서, 아래와 같은 코드를 개발자가 일일이 칠 필요가 없이 스프링 프레임워크 내부에서 자동으로 생성 및 호출을 한다.

ex)
ValidatorFactory factory = Validation.buildDefaultValidatorFactory();
Validator validator = factory.getValidator();
// 생략
Set<ConstraintViolation<Item>> violations = validator.validate(item) // 이 부분이 Bean Validation을 직접 사용하는 부분


Bean Validation의 에러 코드/에러 메시지 설정법에 대한 학습
-> 예를 들어 상품 가격(itemName)에 빈값을 넣게 되면 아래의 @NotBlank에 의해 검증 오류가 발생하며, BindingResult에 오류 입력값과 함께 오류 메시지도 같이 등록이 된다.

@Data
public class Item {

    private Long id;

    @NotBlank
    private String itemName;

    // 생략
}

이때 BindingResult은 아래와 같은 에러 코드를 만들어 내고 해당 코드가 errors.properites에 있는지 확인하고 없으면 defulat 메시지(자바 표준 제공)를 출력시킨다.
codes [NotBlank.item.itemName,NotBlank.itemName,NotBlank.java.lang.String,NotBlank];
default message [itemName]]; default message [공백일 수 없습니다]
-> 결국에느 검증1파트에서 배운 BindingResult의 원리를 그대로 따른다.


BeanValidation 메시지 적용하는 우선 순위
1. 생성된 오류 코드 순서대로 messageSource 에서 메시지 찾기(즉, errors.properties에서 찾음)
2. 애노테이션의 message 속성 사용 @NotBlank(message = "공백! {0}")
3. 라이브러리가 제공하는 기본 값 사용 공백일 수 없습니다
